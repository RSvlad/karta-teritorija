# Профили (речник) и инстанце шаблона

Овај репозиторијум је **шаблон**: један код, а свака инстанца (нпр. „Мој парох“) се разликује само по речима. Шта се у једној инстанци зове „територија“, „престоница“ и како се зову лист и колоне у Sheet-у, налази се у **профилу**: `profiles/<назив>/profile.json`. Код, објављени подаци (`CityData`), имена датотека и интерни идентификатори увек остају исти (`territory`, `capital`, `*.territories.geojson`, `data-pipeline/territories.py`), па се измена шаблона преноси на инстанце без ручног мењања.

## Шта је у профилу

| Поље | Садржај |
|------|---------|
| `name` | Исти као назив директоријума. |
| `app.title` | Назив апликације: наслов странице, `<h1>`, назив инсталиране (PWA) апликације. |
| `app.cachePrefix` | Префикс кеша прегледача (`<префикс>-data`, `<префикс>-map`); мала слова, цифре и `-`. |
| `sheet.territoriesTab` | Назив листа са територијама у Sheet-у. |
| `sheet.territoriesTabAliases` | Старији називи тог листа који још раде (уз упозорење у билду). |
| `sheet.territoryColumn` | Називи колоне са идом територије (први је главни, остали су старији записи). |
| `sheet.capitalKind` | Записи врсте „престоница“ у листу „Тачке“ (мала слова). |
| `forbidden` | Корени речи туђег речника који се не смеју појавити у приказаним текстовима (проверава тест). |
| `text` | Сви текстови које виде корисници и одржаваоци (апликација, поруке билда и извештаја). `{поља}` се попуњавају; морају бити иста као у подразумеваном профилу. |

Подразумевани профил је `teritorije`; он одређује који текстови постоје. Профил мора да изрази **сваки** текст: ништа не пада на туђу реч, па гранање (падежи, род придева: „Најближа престоница“ / „Најближи парохијски храм“) увек пише човек, а не шаблон.

## Који профил је активан

1. променљива окружења `APP_PROFILE` (за пробу: `APP_PROFILE=paroh npm run build`), иначе
2. назив у датотеци `profiles/ACTIVE`.

Јединични тестови (`npm test`) увек користе подразумевани профил, па су очекивања иста у свакој инстанци; `profiles/profiles.test.mjs` проверава све профиле у репозиторијуму. Е2Е тестови (`e2e/`) користе активни профил.

## Додавање текста у шаблону

1. Допишите кључ у `profiles/teritorije/profile.json` и користите га са `tr('кључ', { … })` (`src/profile`), `tr('кључ', { … })` из `profiles/load.mjs` (Node) или `tr("кључ", …)` из `data-pipeline/vocab.py` (Python).
2. Тест `profiles/profiles.test.mjs` пада ако кључ нема сваки профил, ако му се поља разликују или ако се кључ не користи у коду.

Нови текст се не пише у коду: тако се реч никад не заглави у једној инстанци.

## Нова инстанца

1. Направите репозиторијум из овог (GitHub: **Use this template**, или fork) и додајте `profiles/<назив>/profile.json` (копија подразумеваног, са вашим речима; по жељи `forbidden`).
2. У `profiles/ACTIVE` упишите `<назив>`.
3. Замените `README.md` кратким описом инстанце и додајте у `.gitattributes` `README.md merge=ours`, да се README инстанце не преписује при ажурирању.
4. Све остало не дирајте: инстанца мења само `profiles/<назив>/`, `profiles/ACTIVE`, `README.md` и по потреби `.github/workflows/sync-upstream.yml`.

## Ажурирање инстанце из шаблона

`git remote add upstream https://github.com/RSvlad/karta-teritorija.git`, па `git config merge.ours.driver true` (једном, због README-а) и `git merge upstream/main`. Пошто инстанца не мења дељене датотеке, спајање нема сукоба. Ако шаблон дода нов текст, `npm test` у инстанци пада док профил инстанце не добије његову реч: то је намера, а не грешка.

## Подаци објављени у старијем облику

Профил може да има `migrate-previous.mjs`: `restore-previous.mjs` га користи да прочита претходно објављене податке (`upgradeCityData(data)` претвара стари `CityData` у тренутни, `previousGeojsonNames(id)` набраја старе називе датотека са границама). Обрише се када један деплој замени старе податке.
